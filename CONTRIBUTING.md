# Contributing to TechStack-Library 🤝

Thank you for your interest in contributing to **TechStack-Library**!

This repository is a community-driven collection of technical resources, guides, documentation, cheat sheets, and learning materials. Contributions from developers, students, and tech enthusiasts help make it more useful for everyone.

Whether you're adding a resource, improving documentation, fixing a broken link, or suggesting a new category, every contribution is welcome.

## 🛠️ Ways to Contribute

You can contribute in several ways:

- Add technical guides or tutorials.
- Share useful cheat sheets or reference documents.
- Add links to official documentation and learning resources.
- Improve existing documentation.
- Fix broken links or outdated information.
- Add new topics or categories.
- Improve folder organization.
- Suggest improvements to the repository.

## 🚀 Contribution Process

### 1. Fork the Repository

Fork this repository to your GitHub account.

### 2. Clone Your Fork

```bash
git clone https://github.com/<your-username>/<repository-name>.git
```

Navigate into the repository:

```bash
cd <repository-name>
```

### 3. Create a Branch

Create a new branch for your contribution:

```bash
git checkout -b add-new-resource
```

Use a descriptive branch name when possible:

```bash
git checkout -b add-linux-cheatsheet
git checkout -b update-system-design-resources
git checkout -b fix-broken-links
```

### 4. Add Your Contribution

Add your resource to the appropriate directory.

You may contribute:

- Markdown documentation (`.md`)
- Cheat sheets
- Tutorials
- Useful resource links
- Reference material
- Learning roadmaps
- Technical notes

Please follow the existing structure and naming conventions.

### 5. Commit Your Changes

Use clear and descriptive commit messages.

Examples:

```bash
git commit -m "Add Linux command cheat sheet"
git commit -m "Add HTTP status codes reference"
git commit -m "Add system design resources"
git commit -m "Fix broken documentation links"
```

### 6. Push Your Branch

```bash
git push origin add-new-resource
```

### 7. Open a Pull Request

Open a Pull Request against the main repository.

In your PR description, briefly explain:

- What you added or changed.
- Which category it belongs to.
- Why the resource may be useful.
- Any relevant source links.

Your contribution will be reviewed before being merged.

## 📝 Guidelines for Adding Resources

### Quality

- Prioritize reliable, accurate, and useful resources.
- Prefer official documentation when available.
- Ensure the information is relevant to software development or technology learning.
- Avoid adding resources with misleading or inaccurate content.

### Organization

- Add resources to the appropriate category.
- Avoid creating unnecessary folders.
- Use descriptive filenames.
- Keep the folder structure consistent.

### Documentation

When adding a guide or document:

- Use clear headings.
- Keep explanations concise and easy to understand.
- Include examples wherever they help.
- Use Markdown formatting where appropriate.
- Add references or source links when applicable.
- Make the content useful to someone learning the topic.

### Links

When adding external resources:

- Verify that the link works.
- Prefer official documentation, reputable tutorials, and trusted learning platforms.
- Provide a short description explaining what the resource contains.
- Avoid duplicate links unless they serve a different purpose.

## 📄 Suggested Format for Resource Collections

If you're adding a collection of links, consider using this format:

```markdown
# Topic Name

## Official Documentation

- [Resource Name](URL) — Brief description.

## Tutorials

- [Resource Name](URL) — Brief description.

## Cheat Sheets

- [Resource Name](URL) — Brief description.

## Additional Resources

- [Resource Name](URL) — Brief description.
```

## 📄 Suggested Format for Technical Guides

For standalone guides, a simple structure is recommended:

```markdown
# Topic Name

## Introduction

Brief explanation of the topic.

## Key Concepts

Important concepts and terminology.

## Examples

Practical examples, commands, or code snippets.

## Common Mistakes

Things learners should be aware of.

## Further Reading

- Official documentation
- Additional resources
```

You don't need to follow this template rigidly. Use the structure that best fits the resource.

## 🚫 What to Avoid

Please avoid:

- Duplicate resources.
- Broken or unverified links.
- Unrelated content.
- Low-quality or misleading tutorials.
- Copyrighted content copied without permission.
- Promotional content that doesn't provide educational value.
- Large files that aren't necessary for the resource.

## 💬 Questions or Suggestions?

If you have an idea for a new category, aren't sure where your contribution belongs, or would like to discuss a resource before contributing, feel free to open an issue or contact the repository maintainer.

All constructive contributions are welcome!
